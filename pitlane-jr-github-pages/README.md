# pitlane-jr — инструкция по публикации

Подготовлено 23 сентября 2026 года. Это полный статический сайт на HTML, CSS и JavaScript. Устанавливать Node.js, запускать сборку или покупать сервер для этой версии не нужно.

## 1. Сначала проверь сайт на компьютере

1. Скачай архив `pitlane-jr-github-pages.zip`.
2. В Windows нажми по архиву правой кнопкой и выбери «Извлечь всё». Не открывай сайт прямо внутри ZIP.
3. Открой файл `index.html` в распакованной папке. Главная страница откроется в браузере.
4. Перейди по разделам и открой статьи. Фотография и оформление уже находятся в архиве; внешние шрифты и библиотеки не нужны.

## 2. Создай репозиторий

Репозиторий — папка проекта на GitHub с историей изменений.

1. Войди на https://github.com/ или создай аккаунт. Подтверди электронную почту.
2. Открой https://github.com/new .
3. В поле Owner выбери свой аккаунт.
4. В Repository name введи `pitlane-jr`.
5. Выбери Public. Для GitHub Free это позволяет использовать Pages; файлы проекта и опубликованный сайт будут доступны другим людям.
6. Включи Add README и нажми Create repository. Если репозиторий с этим именем уже существует, не удаляй его: используй его, только если он предназначен для этого сайта.

## 3. Загрузи файлы

1. На вкладке Code нажми Add file → Upload files.
2. Открой распакованную папку. Выдели её содержимое и перетащи в окно загрузки GitHub: HTML-страницы, `style.css`, `quotes.js`, `hero.jpg`, `.nojekyll`, `README.md` и `SOURCES.md`.
3. Загружай содержимое папки, а не ZIP и не внешнюю папку целиком. Файл `index.html` должен оказаться непосредственно в корне репозитория, на одном уровне с `style.css`.
4. В сообщении изменения напиши `Add pitlane-jr website`. Нажми Commit changes; если предлагается выбор, для нового личного репозитория выбери сохранение в `main`.
5. Убедись, что в списке файлов виден `index.html`.

Если `.nojekyll` не попал в загрузку, добавь его через Add file → Create new file. Имя — `.nojekyll`. В содержимом можно оставить одну пустую строку. Сохрани через Commit changes. Этот файл отключает обработку Jekyll; собственного генератора у сайта нет.

## 4. Включи GitHub Pages

1. В репозитории открой Settings → Pages.
2. В Build and deployment выбери Source → Deploy from a branch.
3. В Branch выбери `main`, рядом — `/(root)`.
4. Нажми Save. Отдельный workflow создавать не нужно.
5. Открой вкладку Actions и дождись успешного задания публикации Pages. После этого вернись в Settings → Pages и открой выданную GitHub ссылку через Visit site.

Для репозитория `pitlane-jr` обычный адрес имеет вид:

`https://ТВОЙ-ЛОГИН.github.io/pitlane-jr/`

Здесь ТВОЙ-ЛОГИН — имя аккаунта GitHub. Это пример адреса, а не уже опубликованная ссылка. Бесплатного адреса достаточно для начала. Поле Custom domain оставь пустым, пока собственного домена нет.

## 5. Проверь опубликованную версию

- Открывается главная, видны фото и оформление.
- Работают все пункты меню и переходы к статьям.
- В шапке есть цитата, а имя автора открывает её источник.
- На телефоне цитата переходит под название, текст и меню остаются доступными.
- В Car Hunt честно указано, что отправка пока не подключена.

Ссылки и пути к ресурсам сделаны относительными. Поэтому сайт рассчитан и на папку `/pitlane-jr/`, и на корень будущего собственного домена.

## 7. Как обновлять сайт

Для одного файла: открой его на GitHub, нажми значок карандаша, внеси изменение и сохрани через Commit changes. Изменения в `main` будут публиковаться автоматически.

Для нескольких файлов: отредактируй распакованную копию на компьютере и снова загрузи изменённые файлы через Add file → Upload files. Имена и расположение файлов должны совпадать с существующими. Дождись новой публикации во вкладке Actions.

Статьи редактируются в соответствующих HTML-файлах. Шапка и подвал повторяются на девяти страницах: если меняешь название, меню или общий текст, обновляй их на всех страницах. Дизайн меняется в `style.css`.

Главное фото можно заменить своим, сохранив имя `hero.jpg`. Если у снимка другое расширение, обнови ссылки на него в HTML. Обнови описание изображения `alt` и сведения в `photo-credit.html` и `SOURCES.md`.

## 8. Как работают цитаты

В `quotes.js` находится массив `dailyQuotes`. Всего 12 записей; каждая показывается один день, затем цикл повторяется. На всех страницах в один день выбирается одна и та же запись.

Смена рассчитана на 00:00 по Москве (UTC+3), по часам устройства посетителя. Открытая активная страница проверяет смену дня раз в секунду. После возвращения к фоновой вкладке цитата обновляется; браузер может приостанавливать таймеры неактивных вкладок. Если JavaScript отключён, останется исходная цитата Сенны.

Чтобы добавить запись, скопируй один объект в массиве и замени `text`, `author` и `url`. Между объектами нужна запятая. `url` — источник слов, не случайная подборка афоризмов. Не удаляй код под массивом. После изменения количества записей цитата текущего дня может измениться, потому что изменится длина цикла.

В шапке используются короткие фрагменты в русском переводе. Имя автора — ссылка на материал с контекстом. Фанхио цитируется со слов Дэймона Хилла в интервью Formula 1.

## 9. Car Hunt: что работает и что осталось подключить

Сейчас есть описание рубрики. Приёма файлов, личных кабинетов и базы фотографий нет.

Простой вариант для запуска: создать отдельную почту, указать её на странице Car Hunt и принимать снимки с комментариями письмами. Затем вручную отбирать и добавлять материалы в журнал. Нельзя вписывать выдуманный адрес: сначала создай и проверь ящик.

Встроенная отправка через форму потребует отдельного сервиса обработки и хранения. GitHub Pages размещает статические страницы; сам по себе он не обрабатывает загрузку фотографий на сервер. Для текущего тестового сайта это не нужно.

## 10. Если что-то не работает

| Проблема | Что проверить |
|---|---|
| На сайте 404 | Успешно ли завершилась публикация в Actions; выбраны ли `main` и `/(root)`; есть ли `index.html` в корне |
| Отображается README вместо журнала | Загружен ли `index.html` именно в корень выбранной папки |
| Нет оформления или фото | Есть ли `style.css` и `hero.jpg` рядом с `index.html`; не изменился ли регистр имени |
| Видны старые тексты | Дождись завершения Actions и нажми Ctrl+F5 |
| Цитата не меняется при обновлении | Так задумано: одна цитата на сутки; проверь правильность даты и времени устройства |
| Нет ветки `main` в настройках | Сначала сохрани README или файлы первым коммитом; если ветка названа иначе, выбери её |
| Нет настроек Pages | Проверь права администратора репозитория и его публичность для GitHub Free |

## 11. Подключение GitHub к ChatGPT

Для автоматической загрузки через ChatGPT нужна подключённая интеграция GitHub с доступом к целевому репозиторию. Когда предлагается выбор репозиториев, можно дать доступ только к `pitlane-jr`. Пароль и токены не нужно присылать в чат.

После подключения пришли ссылку на целевой репозиторий. Я проверю доступные права и продолжу загрузку в пределах возможностей интеграции. Само подключение не гарантирует право создавать репозитории или включать Pages: недоступный шаг можно выполнить по инструкции выше.
